# Deterministic circuit diagnosis — first executable slice

A model should state a circuit, invoke a checker, then explain its returned
paths and contradictions. It should not repeatedly invent circuit reasoning
in prose. This is a bounded Ithon prototype, using ASE's existing checked
Ithon runner. It is not a wiring diagram, a vehicle repair procedure, or an
approved retrieval passage. Files remain under the excluded `examples/` tree.

## Executable boundary

`circuit.pi` accepts a JSON model and emits deterministic JSON. It implements:

- identified terminals and undirected ideal conductive edges; explicit switch
  states, independent branch protection, source and return paths;
- reversing-load polarity without treating either motor terminal as permanent
  ground; floating, grounded and unknown remain different results;
- enumerated nominal/single-open/unavailable-load/binding hypotheses, retained
  or rejected against observations with named path witnesses;
- test-outcome partitions and additional access/effort costs; a Pareto set
  rather than an arbitrary probability, entropy weight or universal test order;
- the intersection of access steps required by all surviving modeled repairs.
  Diagnosis and repair access are different outputs. Removed trim is not
  charged again; motor and mechanical binding can remain indistinguishable.

The prototype accepts only `scope: synthetic`. This restriction is deliberate:
vehicle source admission and physical pin mapping are not implemented. In
particular, none of the earlier assistant's Honda pin numbers is imported.
`forward` and `reverse` are polarity conventions, not confirmed glass UP/DOWN.

Run with the already provisioned, pinned ASE Ithon frontend:

```text

ithon examples/autogenerated/circuit-checker/circuit.pi examples/autogenerated/circuit-checker/window-demo.json
```

## The regression from this conversation

The synthetic case has one common fuse, an enable contact, and separate driver
and passenger fuses. Passenger motion plus stopped driver motion must reject a
complete open common supply **within the declared model**, while retaining the
driver fuse, driver contacts, door wiring, motor and mechanism possibilities.

There must initially be seven surviving hypotheses. With additional synthetic
observations establishing both switch-side drive rails, the four remaining
candidates are the two door wires, unavailable driver motor and bound driver
mechanism. Every remaining modeled repair then requires opening the door cavity.
That is an access result, not proof that any particular component is defective.

Related field evidence: [PR #14 — Add diagnosis-first A2/A3/A6/A8/A9 fieldbook](https://github.com/the-twin-pines/ASE/pull/14).
The reported car fault remains unresolved; these added observations are test
fixtures, not claims that the user performed them.

## Why not a Regina dependency?

The owned Regina translation is now at `walnut-burgundy/regina`, branch `Agda`.
Its [component module](https://github.com/walnut-burgundy/regina/blob/Agda/agda/COMPONENTS.md)
uses finite graph saturation for simplex connectivity and a doubled state graph
for orientation consistency. Those are relevant algorithmic precedents, but
simplex orientation and manifold validity are not electrical component laws.
No Regina code has been copied or imported into this slice.

Mathematically, a circuit's incidence is a one-dimensional cell complex. With
an oriented incidence matrix B, Kirchhoff current constraints are B i = 0 and
potential-derived edge voltages have the form B^T v (with a fixed sign convention).
Linear resistors add i = G B^T v; voltage sources require the corresponding
source constraints or modified nodal formulation. These are a future electrical
solver, not computations performed by the current reachability checker.

Connectivity alone does not determine voltage under load, current, power,
semiconductor behavior, motor torque or glass movement. Preserve physical
component/terminal identities: a homotopy-equivalent graph can erase the very
wire or fuse that diagnosis needs to distinguish. Diagram crossings are not
junctions unless the source says so.

## Input and inference contracts

All identifiers are explicit. Edge and load records cite a nonempty evidence
label. This label is provenance inside a synthetic fixture, not external source
approval. A state is a complete list of closed ideal edges, or `null` when
unknown; an omitted/unknown state must not silently become all-open.

The source is an ideal two-terminal rail pair. Load endpoints are **not** joined
as zero-ohm wires. A working available load moves with a complete drive pair;
`motor_unavailable` and `mechanism_blocked` stop motion without claiming a
specific current. Observations assume one fixed fault across the named states.
These are declared toy-model laws, not facts established for a real motor.

The bounded hypothesis set is not exhaustive: high resistance, intermittent
faults, multiple faults, backfeed through loads, controller logic, supply
impedance and changing mechanical loads are absent. `no_model_fit` means the
observations and this model disagree, not that the vehicle is impossible.
Even a single surviving candidate is conditional on the declared model.
Unknown predictions never eliminate a hypothesis. No numerical voltage or
Power Probe/test-light reading is silently promoted to an ideal rail fact.

Access costs are caller-supplied nonnegative integer effort units, not inferred
minutes. Tests name their prerequisite access steps explicitly. The Pareto
comparison is a one-step aid, not a globally optimal diagnostic/repair policy.
Common repair access is conditional on the surviving modeled faults; it is not
an instruction to dismantle anything or permission for energizing a circuit.

## Acceptance and known-bad controls

Tests include the separate-fuse regression, source/return and reversal,
floating vs ground, unknown state, ignition-off battery connection, exact path
witnesses, changed access cost, shared repair access, inconsistent observations,
unsupported instrument/physics rejection, invalid endpoints, duplicate identity,
shorted ideal rails and enumeration-order invariance. An independent Boolean
closure oracle checks all 32 active-edge subsets of a small multigraph against
BFS (512 start/target comparisons). Two intentionally bad controls must fail:
all nodes connected, and the original wrongly-cleared-driver-fuse inference.

CI demonstrates only this bounded implementation and fixture behavior. It does
not prove extraction from a factory diagram, improved model advice, a correct
Honda pinout, or successful physical diagnosis or repair.

## Next narrow extensions (not implemented)

1. A reviewed schematic netlist with distinct connector identity, cavity number,
   viewing side, conductor identity, component terminal and source/page anchors.
   Keep visual extraction uncertain until independently reconciled.
2. An Idriç semantic interface separating topology, state, component law,
   observation/instrument, hypothesis and diagnostic/repair action. Preserve
   unknowns and attach source evidence to claims, not merely file presence.
3. A small exact/rational DC solver with instrument loading and high-resistance
   faults, tested against independent circuit calculations. Do not equate a
   voltage indicator with an incandescent lamp or a running motor.
4. Controlled comparison of model answers with and without the checker, using
   held-out circuits and wrong-netlist mutants. Do not use fixture count as
   evidence of improved reasoning.
