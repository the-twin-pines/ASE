# Deterministic circuit diagnosis — executable stub

The model should describe a circuit, invoke deterministic code, and explain the
returned paths and contradictions. This is a bounded Ithon prototype, not a
vehicle wiring diagram, repair procedure, or approved retrieval passage.
It remains under the excluded `examples/` tree.

## What the code owns

`circuit.pi` implements typed finite graphs with stable edge and terminal IDs,
reachability and path witnesses, named operating states, distinct floating and
grounded terminals, reversible drive, bounded fault filtering, test-outcome
partitions, marginal access cost, common repair access and Pareto test comparisons.

`demo.pi` supplies a checked, explicitly synthetic two-window model. It is not a
Honda netlist. It imports no earlier assistant pin or fuse-number assertions.
`tests.pi` checks the actual implementation and rejects known-bad controls.
The tuple storage shapes are documented beside the kernel; they are not a
commitment to the permanent semantic API. There is no generic JSON input parser
in this slice. Model callers use typed Ithon records/arguments; the demo emits
machine-readable JSON.

```text
ithon examples/autogenerated/circuit-checker/tests.pi
ithon examples/autogenerated/circuit-checker/demo.pi
```

## Regression from this conversation

The synthetic case has common protection, an enable contact, and independent
driver and passenger protection. Passenger motion plus stopped driver motion
must reject a completely open common feed **within the declared model**, but
retain the driver's fuse, contacts, door wiring, motor and mechanism candidates.
Seven hypotheses survive initially.

After two additional **synthetic** observations establish the switch-side feed
and return, four remain: two door wires, unavailable motor, bound mechanism.
All four require opening the door cavity. Already-removed trim is not charged
again. The code returns this shared access requirement separately from diagnosis;
it does not instruct anyone to dismantle or energize anything.

These extra observations are fixtures, not measurements attributed to the user.
The actual car fault remains unresolved. Related field evidence remains in
[PR #14 — Add diagnosis-first A2/A3/A6/A8/A9 fieldbook](https://github.com/the-twin-pines/ASE/pull/14).

## Boundaries that must survive expansion

The first layer is ideal conductive connectivity, **not** a voltage/current
solver. Load endpoints are not joined as zero-ohm wires. `floating` means no
ideal-conductor path to a rail in this model; real winding or electronic
backfeed is not calculated. A healthy available load is assumed to move with
complete drive, while the two load-fault hypotheses prevent motion. These are
explicit toy-model laws, not a proof about motor torque or regulator behavior.

Hypotheses cover nominal operation, one open conductor/contact/fuse, or one
unavailable/bound load. High resistance, multiple faults, intermittent behavior,
controller logic, backfeed through loads, instrument loading and changing
mechanical loads are absent. Observations assume one fixed fault across states.
Zero survivors means no fit to this bounded model, not an impossible vehicle;
one survivor is still conditional. Unknown predictions eliminate nothing.

Numerical voltage and test-light/Power Probe readings are not accepted as ideal
rail observations. No hardware actuation API or physical pin mapping exists.
The fixture does not establish OEM source eligibility, and this kernel does
not implement that admission gate. A future real-vehicle adapter must use ASE's
existing source/specification authority, including exact connector viewing side.

Access costs are caller-supplied nonnegative integer effort units, not guessed
minutes. Pareto comparisons are one-step alternatives, not an optimal whole-job
policy. Common repair access is conditional on the surviving candidate set.

## Relation to existing topology code

The owned Regina translation is now `walnut-burgundy/regina`, branch `Agda`.
Its [component calculation](https://github.com/walnut-burgundy/regina/blob/Agda/agda/COMPONENTS.md)
uses finite graph saturation and doubled-state orientation consistency. These
are relevant algorithmic precedents, not electrical component laws. This stub
copies no Regina code and introduces no Regina runtime dependency.

A circuit's incidence is a one-dimensional cell complex. With a consistent
oriented incidence convention, Kirchhoff current constraints are B i = 0 and
potential-derived branch voltages are B^T v. Linear resistor laws add
constitutive equations; voltage sources need their own constraints. That
future DC solver is separate from the present graph checker. Switching,
semiconductors and motor mechanics are not made linear merely by drawing a graph.

Keep physical identities: a topologically equivalent reduction can erase the
particular connector, fuse or wire whose failure must be located. A crossing
on a page is not a junction unless the source establishes one.

## Checks and next boundary

The suite tests separate protection, polarity, floating/unknown, ignition-off
battery connectivity, path witnesses, access accounting, common repair access,
contradictory observations, unsupported instrument rejection, invalid endpoints,
duplicate edge IDs, shorted ideal rails and deterministic replay. An independent
Boolean closure oracle compares all 32 active-edge subsets of a five-edge
multigraph with BFS: 512 start/target comparisons. Wrong all-connected and
wrongly-cleared-driver-fuse controls must both be rejected.

Next work: a reviewed netlist with connector/cavity/view/source anchors; an Idriç
semantic interface separating topology, component laws, state, instrument,
observation and actions; then a small rational DC solver and held-out comparisons
of model answers with and without the checker. Those are not implemented here.
Passing synthetic tests is not evidence of improved model advice or a repaired car.
